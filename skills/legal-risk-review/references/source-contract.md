# 证据来源契约

> 定义「什么算证据、冲突时信谁、取不到时怎么办」。这是本技能最容易被忽略但最关键的一层。

## 来源优先级

| 优先级 | 来源 | 用途 | 说明 |
| :-- | :-- | :-- | :-- |
| 1 | 附件原件（营业执照、银行开户证明、纳税人证明） | 证照类字段的最终依据 | 图片/PDF 原件，非转述 |
| 2 | OA 自动带出的第三方工商数据 | 企业信息比对基准 | 即 R4 所指基准 |
| 3 | OA 表单字段（业务方填写） | 被审对象，不是证据 | 与 1/2 冲突时以 1/2 为准 |
| 4 | 业务方在聊天中的补充说明 | 仅用于澄清事实 | 不得替代证照原件 |

**核心原则**：表单是被审的东西，不是证据。表单与证据不一致，判表单错。

## 先验类型，再看内容

任何附件进入字段比对前，必须先回答一个问题：**这是不是该字段要求的证照？**

拿身份证、合同页、系统截图当营业执照时，后续所有比对都是在错误对象上进行的，结论必然荒谬。类型不符直接 fail，不进入字段环节。

## 逐字符规则

以下字段必须**逐字符**确认，任一位无法确认即不得判通过：

- 统一社会信用代码
- 银行账号

图片模糊、反光、水印遮挡、截断导致无法逐字符读取时 → `需人工核验`，不得按「看起来一样」放行。

> 统一社会信用代码除逐字符外，还须过**格式与校验位硬校验**（GB 32100-2015，见 `supplier-rules.md` 第 0 步）。表单与附件填了同一个错码时，比对会一致，校验位一定报错——这是唯一能抓出「一致地错」的手段。

## 注册资本按数值等价，不逐字符

| 情况 | 判定 |
| :-- | :-- |
| 32.86 亿元 vs 328600 万元 | pass（换算后相等） |
| 32.86 亿元 vs 32.68 亿元 | fail（数值不等） |
| 附件数字位数被遮挡、读不全 | uncertain |

把「写法不同」判成不一致是误杀；把「读不全」判成一致是漏判。两者都要避免。

## 容错范围（仅此三处允许差异）

| 字段 | 允许的省略 | 不允许的差异 |
| :-- | :-- | :-- |
| 注册地址 | 省/市/区层级省略，**省略方向不限** | 双方已出现的同一层级内容冲突 |
| 主体名称 | 无（括号、简称、英文名是否等价属未确认项） | 任何实质差异 |
| 开户行名称 | 无（简称是否允许属未确认项） | 任何实质差异 |

地址判定口径：只比对**双方都写出来的层级**；一方多写出的层级不作为不一致依据；任一共有层级实质冲突即 fail。

## 来源缺失的处理

必须显式区分四种情况，不得合并表述：

| 情况 | 措辞 | 结论 |
| :-- | :-- | :-- |
| 该来源未提供 / 未上传 | 「未提供 X 附件」 | 退回并要求补件 |
| 该来源已读取但字段无法辨认 | 「X 已读取，字段不可辨认」 | 需人工核验 |
| 该来源不在本系统内 | 「未查询 X（数据在 Y 系统）」 | ⚠️ 待补，不得推断不存在 |
| 该来源已上传但**不是该类文件** | 「附件内容与用途不符，未识别为 X」 | **fail 退回**，不得进入比对 |

**「未查到 ≠ 不存在」**：第三种情况严禁写成「无此记录」。

## 输出必须声明的内容

每次审核结论都要写清：

1. 实际读取了哪些来源（列名）
2. 哪些来源未能读取，原因是什么
3. 每个判定字段对应的是哪个来源
4. 无法确认的字段是否已全部标为「需人工核验」

## 禁止

- 用行业常识、历史单据、外部公开信息补全当前单据缺少的字段。
- 把业务方填报的金额、账期当作已验证事实。
- 在来源不足时给出「建议通过」。
- 把他人成果或业务方数据记入审核人的个人产出。
- 在类型校验之前先做字段比对。
