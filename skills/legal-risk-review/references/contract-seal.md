# 合同用印与原件归档细则

> 按需加载。

## 标准流程

办理前核对清单 → 接收与拆解 → 文件流程预检 → 打印用印 → 扫描命名发送 → 原件查找归档 → 邮寄闭环 → 台账结案

## 各环节要求

| 环节 | 要求 | 失败处理 |
| :-- | :-- | :-- |
| 办理前核对 | 确认份数、签署方、用印类型、是否需要骑缝 | 缺信息不开始 |
| 接收与拆解 | 按合同拆成独立件，不混放 | 数量不符当场核对 |
| 流程预检 | 检查审批链是否完整、版本是否为最终版 | 非最终版退回 |
| 打印用印 | 用印前逐页检查；用印中监督并逐份核对 | 漏页/错页立即停止 |
| 扫描命名发送 | 按规范命名后再发送，不发无名件 | 命名不合规则重扫 |
| 原件查找归档 | 原件去向必须可追 | 找不到即升级 |
| 邮寄闭环 | 记录单号与签收 | 无签收不结案 |
| 台账结案 | 闭环后登记 | 缺环节标未完成 |

## 三条硬红线（逆向检查补入）

### 1. 实际用印份数不得超过合同载明份数

| 情形 | 处理 |
| :-- | :-- |
| 实际盖章数 = 合同载明「一式 N 份」 | 正常 |
| 实际盖章数 < 载明份数 | 停止，核对是否漏盖 |
| 实际盖章数 > 载明份数 | **立即停止并上报**。多出的盖章原件一旦流出，公司需对其承担的责任不可控 |

每枚章都要登记：份号、去向、经办人、时间。章数与登记数必须相等。

### 2. 禁止在空白或未完成文本上用印

- 空白页、空白金额栏、空白日期栏、未填写的附件表 → 一律不得用印。
- 「先用印后补内容」属重大风险，任何口头承诺不构成例外，须退回补齐后再走。
- 手写改动处必须有骑缝章或双方书面确认，否则退回。

### 3. 日期倒挂检查

| 检查 | 判定 |
| :-- | :-- |
| 用印日期 早于 审批链最后通过日期 | fail，属未批先印 |
| 用印日期 晚于 合同载明的生效日期 | 需说明原因，标注复核 |
| 合同签署日期 晚于 实际履行开始日期 | 倒签风险，退回并上报 |
| 用印日期与扫描件元数据日期差异过大 | 需人工核验 |

## 用印类型与范围

| 类型 | 适用 | 要求 |
| :-- | :-- | :-- |
| 公章 | 合同正文、协议 | 需审批链完整 |
| 合同专用章 | 合同文本 | 与公章授权范围区分 |
| 骑缝章 | **多页文件（≥2 页）与所有附件页** | 缺骑缝视为用印不完整 |
| 法人章 | 特定条款、银行文件 | 需单独授权记录 |

## 实体章与电子章

| | 实体章 | 电子章/电子签 |
| :-- | :-- | :-- |
| 留痕方式 | 章号登记 + 原件 | 平台签署记录 + 时间戳 + 哈希 |
| 效力核验 | 原件在手 | 须能出具平台签署证书，且签署人身份可追溯 |
| 归档要求 | 原件入柜 | 签署证书 PDF 与原件同等归档 |
| 禁止 | — | 用截图代替签署证书作为效力依据 |

对方主张「已电子签」时，必须索取签署证书而非页面截图；索取不到转人工核验。

## 扫描件完整性

- 扫描件页数 = 原件页数，逐份核对；不一致立即重扫。
- 骑缝章、签字页、附件页必须在扫描范围内。
- 命名规范：`日期_项目_对方主体_版本_状态`，不发未命名或仅编号件。

## 原件流转与作废件处置

| 情形 | 处理 |
| :-- | :-- |
| 对方签收人非合同载明联系人 | 要求授权证明，否则不结案 |
| 邮寄无签收记录 | 不结案，持续跟踪 |
| 用印错误/作废件 | **当场标注作废并收回**，不得留在流转环节；无法收回的立即上报 |
| 退回未用印件 | 退回业务并注明原因，不归档为有效件 |

## 台账与系统状态一致

线下归档完成后，须确认审批系统中的该单据状态已同步为办结。
两边状态不一致（线下已归档、系统仍待办，或反之）→ 不得结案，先对齐。

## 风险判断要点

- 份数与实际签署方不匹配 → 停止并核对。
- 出现手写改动且无骑缝/确认 → 退回。
- 原件去向不明 → 按未完成处理，不得登记结案。
- 章数与登记数不等 → 立即上报，先查章去向再继续。
